三、缺陷修复记录（本轮已全部关闭）

BUG-A 已修复 业务错误码与 HTTP 状态码不一致（系统性，22 处）

根因：core/response.py BizError 默认状态码 400，契约 40401→404 / 40301·40302→403 / 40901·40902→409 / 42201→422 / 42301→423 未生效。

修复：新增 CODE_TO_HTTP 错误码→HTTP 状态映射，BizError.__init__ 未显式传 http_status 时按映射推导；显式传参的 14 处调用点与映射一致，行为不受影响。

验证：22 个契约断言用例（auth/org/matrix/projects/templates/workitems/tasks/documents/agents/notifications）全部转绿，404/403/409 状态码正确返回。

BUG-B 已修复 权限矩阵角色写操作 500（MissingGreenlet）

根因：routes/matrix.py 在 session.commit() 后访问未加载的 Role.members 关系，async 下触发 MissingGreenlet；角色创建/复制/更新/删除 4 个写操作全部 500。

修复：① 新增 _get_role() 统一 selectinload(Role.members) 加载；② 列表查询加 selectinload；③ 新建角色显式初始化 role.members = []，消除 commit 后懒加载。

验证：角色创建/复制/更新/删除/成员分配 5 个用例转绿，接口返回 200 与正确成员数据。

BUG-C 已修复 待审批（invited）用户可直接登录系统

根因：services/auth.py login() 仅校验 locked/disabled，未拦截 invited 状态，注册用户绕过管理员审批直接登录。

修复：login() 在密码校验后、locked 判断前增加 status == "invited" 拦截，返回 403「账号待管理员审批，暂不可登录」。

验证：安全专项用例断言 403 + 提示文案，转绿；注册→审批→登录闭环不受影响。

BUG-D 已修复 归档项目只读保护失效

根因：update_project 仅检查 read_only 字段；seed 项目 p9（archived）缺 read_only=True，可被直接 PATCH。

修复：① 更新校验改为 read_only or status == "archived" 双重拦截；② seed 数据 p9 补 read_only: True。

验证：接口归档链路（archive→PATCH 403）与 seed 一致性用例均转绿。

观察项修复 已处理（部分）

① documents 列表补 order_by(DocItem.id.desc())，分页顺序稳定（已修）；② main.py 未使用导入 get_current_user 清理（已修）；③ BizError 弃用常量替换为 HTTP_422_UNPROCESSABLE_CONTENT（已修）。

待处理（P2）：前端 ESLint 26 errors（canvas.tsx 8 处、app-store.tsx react-refresh 3 处等）、主 bundle 1.02MB 代码分割、存储型 XSS 前端转义确认。

注：测试期间检测到代码基线外部变更——GET /documents/{id}/content（短时链接签名校验）与 GET /tasks/{id}/context（结构化上下文）端点被移除、task_context.py 删除、create_link 简化为 UUID token。对应 3 个测试用例已同步移除，建议确认是否为预期重构（当前 link 生成的 token 无签名校验，若需保留下载链路请补充实现）。
