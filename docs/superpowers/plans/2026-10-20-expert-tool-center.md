- New model module models/tool.py: ToolDefinition, ToolVersion, ToolInvocation, ToolAutomationJob. Root imports these in models/__init__.py. ToolVersion ID is what grants and node rules pin.
- ExpertVersion.tool_bindings JSON list default=[] (root owns model + migrations + schemas + experts routes). Binding objects use tool_version_id, scope='current_work_item', approval='inherit'|'required'; cannot relax definition policy. API responses expert versions expose toolBindings.

- ToolDefinition: id, slug, name, description, source ('native','mcp'), server_id nullable, external_name, status ('active','disabled'), current_version_id, created_by, created_at, updated_at.
- ToolInvocation: id, idempotency_key unique, tool_version_id, expert_version_id nullable, run_id nullable, generation, task_id nullable, requested_by, source ('expert','automation','test'), input_json, result_json, status ('queued','awaiting_approval','running','succeeded','failed','unknown','denied'), error, approval_status ('not_required','pending','approved','rejected'), decided_by, created_at, finished_at. IDs strings32/40 matching existing models.
- ToolAutomationJob: id, event_key unique, task_id, run_id nullable, generation, expert_version_id, rule_json, payload_json, requested_by, status ('queued','running','succeeded','failed'), error, result_json, attempts, claim_token, lease_until datetime timezone nullable, created_at, finished_at.
