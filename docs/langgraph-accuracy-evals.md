# LangGraph 准确性回归评测

本项目把「结构化可采纳」定义为 schema 校验通过；Judge 必须明确返回 `{"pass": true, "issues": []}` 才算事实核验通过。Judge 响应不可解析、校验服务故障或达到修订上限，均会被记录为可观察的人工复核信号，不能被误报为「已通过」。

## 发布前门槛

- 执行 `cd backend && uv run pytest tests/test_expert_accuracy.py tests/test_experts.py tests/test_ai_fill.py`。
- 必测场景：完整 ID 精确检索、证据和回答冲突、Judge 非 JSON、修订时保留上一版、必填字段、枚举、多选、数字和日期无效值。
- 节点型 Expert 必须仅注入当前处理人可读的工作项、前序表单和关联文档；无权限或无证据时不得用目录摘要替代事实依据。
- 已绑定 Skill 必须是已发布资源，运行时只在内存读取其 `SKILL.md`；不可用 Skill 应留下运行事件，但不得放宽既有事实与审批约束。
- 新增 Expert、模型、提示词或检索策略时，使用同一组固定样本对比基线；不得只以主观示例判断效果。

## 指标与升级规则

对每个版本记录：事实正确率、可引用证据覆盖率、schema 一次通过率、错误自动采纳率、人工复核率、平均调用次数和端到端延迟。优先降低错误自动采纳率；若某项改动使其升高，禁止自动发布。

## 下一阶段

当前知识库 ID 与 Skills 已能在 Expert 版本中配置，但项目尚未有可授权检索的知识库文档索引。因此在引入知识库数据模型、分块/索引、权限过滤和引用元数据前，不应把「已绑定知识库」表述为已经参与推理。该能力上线后，将知识库命中率、引用正确率和权限越界率加入上述固定集。
