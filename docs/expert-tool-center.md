# Expert 工具中心与验收归档

工具中心管理平台原生工具和已批准出站 MCP 服务发现的工具。原生执行器由代码注册；页面不能创建任意脚本或 HTTP 执行器。

## 配置流程

1. 在「工具中心」查看工具版本、输入/输出 Schema、风险及审批要求。原生工具可以调整风险与审批策略；修改产生新版本。
2. MCP 工具先在资源管理配置出站 Streamable HTTP 服务，再执行工具发现。为远端目标参数配置当前工作项/任务上下文映射，创建草稿、真实测试、审批并发布。至少一个参数必须绑定当前工作项或任务；仅绑定项目不够。未绑定参数仅允许平台支持的正文、标题等负载字段；其他目标参数需要专用连接器。缺少可执行任务范围映射的版本不能授权给 Expert。
3. 在 Expert 版本编辑页勾选工具，固定具体版本；授权范围为当前工作项，可以要求额外审批。发布新 Expert 版本后创建 Deployment，历史 Deployment 保留原绑定。
4. 在验收结束节点选定 Deployment，配置「进入节点」与「Expert 产出校验通过」归档规则，再发布流程模板。

MCP 工具默认要求审批。预览只验证参数，不能代替发布所需的真实测试。审批恢复仍以原发起人、当前任务权限及已冻结工具版本执行；停用工具立即阻止后续执行。未知结果的远端写入不能自动重放，应人工核查远端结果。

## 文档归档行为

进入验收节点时，自动化冻结实际完成前序节点中已采纳 FILE/UPLOAD 字段的文档引用及校验和。需求起始资料、未完成分支和无授权文档不会被批量归档。归档保存独立对象与文档中心记录，保留来源、工作项、节点及内容校验和；重复执行复用相同归档。

任务总结必须来自成功运行且通过格式校验的输出，并匹配输出哈希。总结标识「AI 生成／待人工验收」；格式校验通过不代表事实核实或人工验收通过。自动化不提交验收任务。

## 查看与故障处理

节点页及运行中心展示自动化任务、工具调用、审批和文档链接。失败任务可重试；重试保留原身份和冻结输入，权限或源文件发生变化时应先检查原因。已在验收中的任务可点击「补执行」，归档已有交付物并安排一次总结生成；重复点击复用同一补执行记录。

数据库迁移新增工具台账、自动化队列及文档归档字段，历史 Expert 默认无新增授权。生产兼容迁移脚本位于 `backend/scripts/cutover_acceptance_tools.py`：先生成受保护备份并审查校验和，再应用明确列出的实例和项目绑定。回退时停止相关待执行队列，恢复旧绑定及代码；保留已归档文档与审计记录。不要直接对生产库运行测试初始化脚本。
