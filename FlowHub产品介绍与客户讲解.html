一、产品概述

一句话定位：FlowHub 是把「企业业务流程」和「AI 专家能力」深度融合的一体化协同平台——既能把线下散乱的工作流搬到线上标准化执行，又能让 AI 以"专家节点"的身份参与真实业务，全程可控、可审批、可审计。

我们解决什么问题

客户痛点现状FlowHub 的方案
流程靠人肉推进需求/变更靠微信群、Excel 传递，状态不透明、责任不清可视化画布编排流程，任务自动流转、超时预警，全程留痕
流程知识无法沉淀老员工的经验只在脑子里，人走流程断流程模板化、版本化管理，可复用、可复制、可传承
AI 用起来不受控员工私下用各种 AI 工具，数据泄露风险大、结果不可信企业统一 AI 专家平台：权限受控、工具审批、全链路审计
AI 与业务两张皮AI 只做问答聊天，无法真正处理业务AI 作为流程节点执行任务，读写业务数据、提交表单、触发下一步
人机协作低效AI 的结果没人敢用、没人把关，人机工作割裂节点级"人机接力"：AI 先干活、人再确认；高风险动作必须人工审批后才执行

二、核心价值主张

🏛️ 对管理层：看得见、管得住、可追溯

流程状态一屏掌握——领导看板呈现运行中流程、超时任务、部门负载、节点热区，管理从"靠问"变"靠看"。AI 使用可控可审计——所有 AI 动作留痕，高风险操作必须人工审批，杜绝"黑盒 AI"。数据安全有边界——文档敏感分级（L1/L2/L3）、短时授权链接、细粒度 RBAC 权限。

👥 对业务团队：流程标准化、执行提效

把流程"画"出来——非技术人员也能用画布搭建流程。任务自动流转——节点处理人按角色/技能自动匹配，SLA 超时预警，责任到人。AI 帮你干活——AI 专家可直接处理任务、填写表单、汇总上下文，人做决策、AI 做执行。

💻 对 IT/技术团队：开放、标准、好集成

标准 MCP 协议——企业系统（ERP/CRM/IM/数据库）通过 MCP 接入，AI 能力即插即用。开放 API + 操作 Skill——外部智能体可下载 FlowHub 操作 Skill，用 Access Key 安全接入。企业私有化部署——Docker 容器化，数据落在企业自己的 PostgreSQL/MinIO 存储中。

🤝 对所有人：人机协同，AI 干活、人把关

AI 不替代人，而是帮人干活——AI 承担重复、耗时、检索分析类工作，人保留最终决策权。协同有边界——提交、上传、创建子任务等动作必须人工批准后才执行，每一个"人机握手点"都是强制边界。过程透明可解释——AI 的每一步（读了什么、调了什么工具、得出什么结论）都实时展示并留痕，人始终看得懂、查得到、改得了。

三、核心功能详解

3.1 流程协同引擎

把企业任意工作流（需求、问题、变更）从线下搬到线上，标准化、自动化、可追踪。

能力说明
可视化流程画布拖拽式编排，节点类型：开始 / 任务 / 决策 / 并行分叉 / 并行汇合 / 验收 / 闭环确认 / 定时 / 结束
版本化模板模板生命周期：草稿 → 评审 → 发布 → 废弃 → 归档；发布前自动校验（6 项规则）
项目-模板绑定一个项目可绑定多套流程模板（需求/问题/变更），节点处理人绑定用户 + 角色/技能
工作项生命周期需求/问题/变更三类工作项，11 种状态全生命周期管理（草稿→提交→处理→验收→闭环）
任务流转闭环认领 / 转办 / 退回 / 提交推进 / 验收 / 闭环确认，全程幂等保护防重复提交
SLA 与超时每个节点可配置 SLA 时限（默认 24h），超时自动标记并预警
上下文继承前序节点表单按节点折叠展示，原处理人可结构化补充信息，独立留痕不覆盖原值
客户发起需求→ 需求分析AI 辅助→ 技术评审
决策分支→ 开发任务
并行分叉→ 验收→ 闭环确认→ 结束

3.2 Expert OS —— 企业 AI 专家平台

把 AI 从"聊天工具"升级为"企业员工"——有身份、有技能、有权限、可审批、可追溯。

Expert 生命周期管理

创建草稿→ 配置提示词/模型/技能/知识库→ 测试真实运行验证→ 发布不可变快照→ 部署绑定流程节点→ 运行监控
  • 支持内置 Expert（平台预置）与自建 Expert（企业自定义）
  • 版本化：每个发布版本不可变，运行记录可复现、可追溯、可回滚
  • 发布校验：自动检查提示词/模型/技能/知识库/审批策略是否齐备，阻断项明确提示
  • 一键测试：编辑器内直接发起真实运行测试，验证通过才允许发布

Expert Skill（专业能力包）

将专业指令、输入输出约束、工具权限打包为版本化能力包（ZIP/TAR/GZ），生命周期：草稿 → 测试 → 发布 → 弃用；一个 Skill 可复用于多个 Expert，能力可沉淀、可传承。

工具接入与治理（MCP 中心）

方向含义
native 内置FlowHub 内置领域能力：查任务、读文档、提交表单、上传文档、创建子任务等 20+ 工具
inbound 对外对外暴露的 FlowHub MCP Server，供外部智能体接入
outbound 接入接入的外部 MCP Server（企业 ERP/CRM/IM 等）

工具风险五级管控：只读 → 生成建议 → 保存草稿 → 提交变更 → 关键动作。提交/上传/创建子任务等动作中断执行、等待人工批准后才执行一次；关键动作（提交/退回/转办/暂停/恢复/关闭）默认拒绝，需显式策略放行。

Provider 中心 · 知识库 · 运行治理

🔌Provider 中心

统一管理多家 LLM 供应商（Base URL / API Key / 模型列表），连接检测与健康度监控，密钥不落地明文。

📚知识库与记忆

企业文档 → 分块 → 向量化（pgvector）→ 检索引用可追溯；三级记忆命名空间（Expert/任务/运行级），留存策略可配置。

📊运行中心

每次 AI 运行全量记录：状态、Trace、工具调用、耗时、结果；可导出运行记录。

✅审批队列

高风险动作实时进入审批队列，批准 / 拒绝 / 过期全留痕；批准后仅执行一次对应运行。

3.3 人机协同机制（Human-AI Collaboration）⭐

FlowHub 不是"让 AI 替人做事"，而是把人和 AI 编排进同一条流程，形成"AI 干活、人把关、全程透明"的协作闭环。

六种人机协同模式

模式谁做什么系统落地机制
① AI 执行、人审批AI 提出动作，人批准后才真正执行高风险工具（提交/上传/创建子任务等）触发运行中断，进入审批队列，批准后仅执行一次
② 节点级人机接力流程节点既可由人处理，也可绑定 Expert 由 AI 处理画布节点绑定 Expert 部署；AI 处理结果与人工表单在同一处理页呈现，待 AI 审批状态标记，人确认后任务继续流转
③ AI 辅助人AI 汇总上下文、起草方案、检索知识，人决定是否采纳只读/生成类工具直接执行，结果展示在节点处理页与 AiChat 中，供人参考
④ 人机对话人主导、AI 协作的对话式任务完成AiChat 绑定已发布 Expert，工具调用过程实时可见，产出可下载
⑤ 人在环治理AI 的"上岗"全程人说了算Expert 生命周期（创建/测试/发布/部署/停用）全部由人操作，发布前强制校验
⑥ 外部智能体接力 ⭐平台内部处理不了的节点，委托给企业外部智能体接着解决通过 MCP + Access Key 接入后自动获取活动节点上下文与继承的上下文（当前任务 + 全部已执行上游链条），处理完成后自动回传节点结果，平台校验后自动推进流程

一个典型的人机协同流程

人发起工作项→ AI 汇总上下文、起草方案直接执行→ AI 尝试提交表单运行中断→ 审批队列 → 人审查批准→ AI 继续执行下一步→ 人验收 · 闭环

外部智能体接力节点处理（平台内部处理不了时）⭐

FlowHub 节点任务人未认领 / 内部 Expert 处理不了→ 外部智能体下载 Skill + MCP 配置Access Key 接入→ 自动获取上下文task.context.get→ 外部智能体处理产出结果→ 自动回传节点结果task.submit / task_form.commit→ 平台校验 → 流程自动推进
自动获取的上下文内容
活动节点上下文当前节点的任务信息、表单 schema、处理要求——外部智能体知道"这一步要我做什么"
继承的上下文上游所有已执行节点的处理结果、表单值、追加说明（完整链条）——外部智能体知道"前面发生了什么"，与画布上人的视角完全一致

关键点：系统中的"人机握手点"（审批）是运行时强制边界，不是可选项；AI 的每一步都实时展示并留痕，人始终看得懂、查得到、改得了。上下文自动获取、无需手动拼接——一次调用拿到"当前活动节点 + 全部继承上下文"，获取权限由 can_read_task（执行人或管理员）+ per-user Access Key 闸控。外部智能体与内部专家一视同仁——只能看到授权范围内的数据、必须通过受控工具提交结果、每一次提交都留痕可审计，平台不因"外部"而放松边界。

4.3 安全与合规设计

  1. 纵深权限：每次 AI 工具调用的有效权限 = 用户 RBAC ∩ Expert 策略 ∩ Skill 策略 ∩ 工具策略 ∩ 项目范围 ∩ 任务数据范围 ∩ 文档敏感级别 ∩ 审批状态
  2. 执行边界审批：审批是运行时强制边界（LangGraph interrupt/resume），不是事后标记
  3. 密钥安全：API Key 明文仅创建时展示一次，落库 bcrypt 哈希；Provider 密钥不落明文
  4. 数据可见性最小化：外部智能体只能读取授权范围内的任务与上游链条数据
  5. 完整审计：AI 运行、工具调用、审批、导出均入审计，可复现可追溯

五、典型应用场景

1跨部门审批流程 + AI 助理

客户发起需求 → 系统按模板创建流程 → AI 专家自动汇总上下文并起草方案 → 决策节点分派 → 部门并行处理 → 验收闭环。全程看板可视，超时自动预警。

2企业自建"业务专家"

HR、法务、客服等部门无需写代码，用 Expert 编辑器配置提示词、绑定技能与知识库、设定风险工具与审批策略，即可发布一个"懂业务的 AI 员工"，挂载到流程节点自动执行。

3AI 工具安全可控落地

所有 AI 通过平台统一出口：读什么数据、调用什么工具、做什么动作，全部受权限约束并留痕；提交类动作必须人工批准。

4外部智能体接入企业系统 ⭐

企业已有 Cursor / 自研 AI 助手等外部智能体，下载 FlowHub 操作 Skill 与 Access Key 即可在授权范围内操作企业任务与数据。当某个流程节点平台内部处理不了时，可将节点委托给外部智能体接着解决，处理完通过 MCP 工具自动回传节点结果，流程自动推进——形成"外部 AI + 企业流程"的完整协同闭环。

5人机协同的日常办公 ⭐

上班打开"我的任务"——AI 已把待办任务的背景、前序上下文、相关文档全部汇总好；你审查 AI 起草的方案后提交；AI 要提交表单时会停下来等你批准；遇到不确定的问题，在 AiChat 里和业务专家对话几句就能得到带引用的答案。人的时间花在判断上，重复劳动交给 AI。

七、常见问题 FAQ

Q1：FlowHub 和传统的 OA / 流程审批系统有什么区别？

传统 OA 是"流程记录器"，FlowHub 是"流程 + AI 执行引擎"。除了把流程搬上线，FlowHub 的核心差异在于 AI 专家能直接参与流程执行（读上下文、填表单、调工具），并且全程受权限与审批约束——这是传统 OA 不具备的。

Q2：AI 会不会乱做事？数据安全怎么保证？

三层保障：① 权限最小化——AI 只能操作你授权范围内的数据；② 工具分级——只读/生成类直接执行，提交/关键动作必须人工审批；③ 全审计——每个 AI 动作留痕可追溯。另外支持私有化部署，数据存在企业自己的服务器上。

Q3：我们公司没有开发人员，能用起来吗？

能。流程画布是可视化拖拽的，Expert 配置也是表单化的，业务人员经过简单培训即可搭建。同时平台提供组织同步、渠道配置等开箱即用能力。

Q4：能接入我们现有的系统和 AI 模型吗？

可以。模型侧支持任意 OpenAI 兼容 API（多家供应商统一管理）；系统侧通过标准 MCP 协议接入企业 ERP/CRM/IM/数据库；对外提供 REST API 与操作 Skill，供外部智能体集成。

Q5：部署和运维成本高吗？

平台 Docker 容器化交付，核心依赖 PostgreSQL + Redis + MinIO 即可运行，支持私有化部署与横向扩展。一次性建设，长期沉淀企业流程与 AI 资产。

Q6：目前产品成熟度如何？

流程引擎与权限/审计/通知等底座已完成系统测试（约 200 个用例，覆盖权限安全、流程闭环、接口健壮性）；Expert OS 正处于"本地优先验证 → 后端全面接入"的加速迭代期，本周已打通 Expert 全生命周期（创建 → 测试 → 发布 → 部署 → AiChat 执行）的数据链路。

Q7：AI 会替代我们的员工吗？

不会，FlowHub 的设计前提就是"人机协同"而非"AI 替代人"。AI 负责重复、耗时、检索分析类工作（起草、汇总、填草稿），人保留最终决策权；所有提交类、关键类动作都必须人工批准后才执行。系统里的每个"人机握手点"都是强制边界，AI 是给员工增效的助手，而不是对手。

Q8：平台处理不了的节点，外部智能体怎么接着处理？

外部智能体通过 MCP + Access Key 接入平台后，可调用平台上下文工具（如 task.context.get）自动获取活动节点的上下文以及沿上游链继承的上下文（当前任务信息、节点表单、上游各节点的处理结果与追加说明，无需手动拼接）；在平台外处理完成后，通过标准 MCP 工具（如 task.submit / task_form.commit）自动回传该节点的处理结果，平台校验通过后自动把流程推进到下一节点。整个过程与内部专家同一套权限边界：最小授权（can_read_task + per-user Access Key 闸控）、受控提交、全程留痕可审计。
